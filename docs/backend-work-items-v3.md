# 영양성분 기준 v3 백엔드 작업 명세

작성일: 2026-10-07  
검토 대상: `영양성분_기준_v3.zip`의 계산 명세서, 처리 기준, 참조 구현, 기준값표·매개변수표, 영양소별 처리 일람  
비교 대상: 현재 FastAPI 백엔드 `app/catalog.py`, `app/engine.py`, `app/models.py`, `data/products.json`, `tests/test_engine.py`

## 결론

현재 백엔드는 제품 해시 조회, Trie 검색, 고정 순서 누적 배열, 최대 힙 추천, 선택 후 재평가라는 구조는 갖췄다. 그러나 v3의 계산 모델을 구현한 백엔드는 아니다. 현재는 FEDIAF 2025 기반 6개 성분 엔진이고, v3는 NIAS 중심 44개 기준 데이터와 18개 1차 구현 성분, 별도 성장곡선과 단위 환산 체계를 요구한다.

가장 큰 차이는 기준 출처만이 아니다. 성체 열량 계수, 고양이 성장 단계, 강아지 성장 입력, 칼슘 예외, 추천 안전 여유와 중복 점수의 정의가 다르다. 따라서 기존 상수를 덮어쓰면 안 된다. `FEDIAF-2025.09`와 `NIAS-v3`를 구분하는 버전형 계산 엔진으로 추가한 뒤 동일 요청에 어떤 기준 버전을 썼는지 응답해야 한다.

## 현재 구현과 v3 차이

| 영역 | 현재 백엔드 | v3 요구 | 판정 |
| --- | --- | --- | --- |
| 기준 버전 | FEDIAF 2025 단일 버전 | NIAS 표 2-17 중심, AAFCO·FEDIAF 예외값 | 신규 기준 버전 필요 |
| 성분 수 | 6개 | 원본 44개, 1차 구현 제안 18개 | 미구현 |
| 단위 | mg·µg 중심 | g·mg·µg·IU 고정 단위 | 재설계 필요 |
| 성견 열량 k | 95 | 110 | 불일치 |
| 성묘 열량 k | 75 | 100 | 불일치 |
| 고양이 성장 | 한 단계, k=100 | 3단계, k=225/187.5/150 | 미구현 |
| 강아지 성장 | 예상 성체 체중 직접 입력 | 체급별 성장곡선으로 비율·성체 체중 계산 | 다른 모델 |
| 개 성장기 칼슘 | 15 kg·6개월 조건으로 최소값 변경 | 예상 성체 31.75 kg 이상이면 상한 4.5 적용 | 불일치 |
| Ca:P | 생애주기별 상한 1.6/1.8/2.0 | 개 공통 1~2 | 불일치 |
| 주의선 | 상한×75%/50% | 예외 주의값 우선, 없으면 상한×비율 | 일부 구현 |
| 기준 없음 | 최소·상한이 모두 없으면 기준 없음 | 최소·상한·주의가 모두 없으면 기준 없음 | 주의선만 성분에서 오류 가능 |
| 사료 추정 | 제품 성분표 전체가 비었을 때만 하한 추정 | 성분별 실제값이 없을 때 해당 성분만 추정 | 부분 성분표 처리 미구현 |
| 제품 급여량 | 단일 `recommendedDailyAmount` | 체중 구간별 `dose_by_weight` | 미구현 |
| 안전 여유 | 상한 기준 여유의 평균 | `(주의선-trial)/(주의선-하한)`의 최솟값 | 불일치 |
| 중복 점수 | 부족·기준 없음이 아닌 후보 성분 수 | 현재 급여 중 영양제와 겹치는 성분 수 | 불일치 |
| 후보 제외 | 이미 선택한 후보만 제외 | 이미 급여 중인 제품과 선택 제품 모두 제외 | 일부 누락 |
| 검산 | 현재 엔진 회귀 테스트 17개 | T1~T16 골든 케이스 | 별도 테스트 필요 |

## 백엔드 작업 목록

### P0. 기준 버전 경계 확정

**BE-V3-001 기준 프로필 버전 모델 추가**

- `standardProfile`을 `FEDIAF_2025` 또는 `NIAS_V3`로 명시한다.
- 분석·추천 요청과 응답, 기록 데이터에 버전을 저장한다.
- 버전이 없을 때 기존 배포 호환성을 위해 현재 기본값을 유지하거나 API 버전을 `/api/v2`로 분리한다.
- 서로 다른 기준값을 한 `STANDARDS` 객체에 섞지 않는다.

완료 조건:

- 응답의 기준 버전·출처·단위 체계가 명확하다.
- 같은 입력을 두 기준으로 실행해도 캐시·기록·추천 결과가 섞이지 않는다.

**BE-V3-002 기준 출처 승인 상태 저장**

- 각 기준값에 `sourceDocument`, `table`, `sourceYear`, `verificationStatus`, `verifiedAt`을 둔다.
- ZIP의 EU 법정 주의값은 원문 대조 필요로 표시되어 있으므로 검증 전 `PENDING_VERIFICATION`으로 저장하고 운영 판정에는 사용하지 않는다.
- 사용자 확정 정책값과 공인 문헌값을 별도 필드로 구분한다.

완료 조건:

- 출처 미검증 값은 실제 공식 기준처럼 노출되지 않는다.
- 관리자나 테스트가 미검증 기준의 활성화를 막는다.

### P0. 기준 데이터 계층

**BE-V3-003 44개 영양소 마스터 작성**

- 정수 성분 ID 1~44와 안정적인 문자열 키를 함께 사용한다.
- 이름, 분류, 기준 단위, 종·생애주기별 최소·최대·예외 주의값, 구현 여부를 JSON 또는 버전 관리 가능한 데이터 파일로 옮긴다.
- 빈칸은 반드시 `null`로 보존한다.
- 1차 API는 구현 승인된 18개만 분석하되 전체 44개 마스터는 조회 가능하게 한다.

완료 조건:

- 행 수 44개, ID 중복 없음, 단위 누락 없음, 생애주기 열 누락 없음.
- 비타민 K처럼 모든 기준이 비어 있는 성분도 삭제하지 않는다.

**BE-V3-004 매개변수 설정 파일 분리**

- 열량 계수, 성장 경계, 성장곡선, 주의 비율, 추천 가중치, `top_n`, 사료 가정 배수를 코드 밖 버전 데이터로 옮긴다.
- 시작 시 스키마 검증 후 불변 객체로 적재한다.
- 기준 버전과 매개변수 버전을 함께 응답한다.

완료 조건:

- 계산 코드에 `110`, `2.25`, `31.75`, `10/5/1` 같은 정책 상수가 직접 남지 않는다.
- 설정 누락·범위 오류가 있으면 서버 시작이 실패한다.

### P0. 계산 엔진

**BE-V3-005 나이 정규화와 생애주기 확장**

- `weeks = month × 4.345`, `months = weeks / 4.345`를 한 번 계산한다.
- 개: 미지원/초기 성장/후기 성장/성체.
- 고양이: 미지원/성장1/성장2/성장3/성체.
- 경계값 8주, 14주, 4개월, 9개월, 12개월을 골든 테스트로 고정한다.

완료 조건:

- 3개월 개가 약 13.035주로 초기 성장기에 들어간다.
- 고양이 성장 단계마다 열량 계수가 달라진다.

**BE-V3-006 강아지 성장곡선 계산기 추가**

- 체급별 `a × ln(weeks) − b`로 성체 체중 대비 비율을 계산한다.
- 비율은 100%에서 제한한다.
- 예상 성체 체중 원값과 체급 범위 절단값을 모두 반환한다.
- 범위를 벗어나면 경고를 제공한다.
- 기존 `expectedAdultWeightKg` 입력을 유지할지, 체급 기반 계산으로 전환할지 호환 정책을 정한다. 권장 방식은 둘 다 받되 체급 계산값과 직접 입력값의 차이를 검증하고 어느 값을 사용했는지 응답하는 것이다.

완료 조건:

- T3~T5가 참조 구현과 허용 오차 안에서 일치한다.
- `adultSize`와 체중이 모순되면 조용히 절단만 하지 않고 경고를 반환한다.

**BE-V3-007 NIAS 열량 계산 프로필 추가**

- 성견 110, 성묘 100을 적용한다.
- 고양이 성장 단계별 225/187.5/150을 적용한다.
- 강아지는 성장곡선 비율로 `254.1 − 1.35×비율(%)`을 계산한다.
- 현재 FEDIAF 계산식과 함수 또는 전략 객체를 분리한다.

완료 조건:

- T1~T6 기준 열량이 참조 구현과 일치한다.

**BE-V3-008 성분별 기준선 계산 일반화**

- 44개 영양소의 생애주기 열 매핑을 데이터로 처리한다.
- 예외 주의값 → 상한×종별 비율 → 없음 순서를 구현한다.
- 개 성장기 칼슘은 v3 기준의 31.75 kg·상한 4.5 조건을 적용한다.
- `minimum`, `caution`, `upper` 각각에 값과 근거 유형을 함께 반환한다.

완료 조건:

- 주의선만 있는 구리·철·망간·아연·고양이 셀레늄이 `NO_STANDARD`로 오판되지 않는다.
- `classify`의 기준 없음 조건이 세 선 모두 `null`인지 확인한다.

**BE-V3-009 부분 성분표 사료 합산 수정**

- 제품 전체가 비었는지가 아니라 성분별로 실제값 존재 여부를 검사한다.
- 실제값이 있는 성분은 실제 급여량으로 계산한다.
- 값이 없고 완전사료이면 해당 성분의 하한×사료 가정 배수를 추정한다.
- 값이 없고 완전사료가 아니면 0이 아니라 `UNKNOWN_CONTRIBUTION` 여부도 함께 반환한다. 계산 합계에는 정책상 0을 쓰더라도 정보 없음과 실제 0을 구분한다.

완료 조건:

- 한 제품에서 칼슘은 실제값, 비타민 D는 추정값으로 동시에 표시할 수 있다.
- 제품별·성분별 provenance가 결과에 남는다.

### P0. 단위와 제품 데이터

**BE-V3-010 성분별 단위 환산 서비스 구현**

- g/mg/µg 접두 단위를 변환한다.
- 비타민 A·D·E의 IU 변환은 원료 형태를 함께 받아 처리한다.
- EPA와 DHA를 합산하되 총 오메가3만 있는 값은 EPA+DHA로 사용하지 않는다.
- %, mg/kg, IU/kg, ppm, 1000 kcal당, 건물 기준 입력을 정규화한다.
- `이상/이하` 보증값은 실제 함량으로 합산하지 않는다.

완료 조건:

- 변환 결과에 원문 값, 원문 단위, 환산식, 기준 단위, 원료 형태, 출처를 저장한다.
- 물질 형태나 수분·열량 정보가 없으면 추측하지 않고 `INSUFFICIENT_DATA`를 반환한다.

**BE-V3-011 제품 스키마 확장과 검증**

- `hasDetail`, `contents`, `contentBasis`, `doseByWeight`, `tags`, 데이터 출처, 갱신일, 품질 상태를 추가한다.
- 영양제 권장량은 체중 구간이 정렬되고 겹치지 않는지 검사한다.
- 사료 함량은 1 g당, 영양제는 1회 제공량당 기준으로 정규화한다.
- 알 수 없는 성분 ID, 음수 함량, 잘못된 단위를 서버 시작 시 거부한다.

완료 조건:

- 제품 데이터 검증 실패가 계산 중 `KeyError`가 아니라 적재 단계 오류로 나타난다.

### P0. 추천 엔진

**BE-V3-012 후보 권장량과 제외 조건 수정**

- 단일 권장량 대신 `doseByWeight`에서 현재 체중 구간의 급여량을 선택한다.
- 이미 급여 중인 제품과 이미 선택한 제품을 후보에서 제외한다.
- 성분별 주의·과다와 Ca:P 비율을 가상 추가 후 재검사한다.

완료 조건:

- 같은 제품이 중복 추천되지 않는다.
- 권장량 구간 경계값 테스트가 있다.

**BE-V3-013 추천 점수식을 v3 정의로 수정**

- 보완 수: 현재 부족 성분이 부족에서 벗어나는 개수.
- 안전 여유: 후보가 포함한 주의선 적용 성분별 `(주의-trial)/(주의-lower)`의 최솟값. 평균을 사용하지 않는다.
- 후보가 해당 성분을 포함하지 않으면 점수 계산에서 제외한다.
- 중복 수: 후보 성분과 현재 급여 중인 영양제 성분의 교집합 크기.
- 가중치는 설정 파일에서 읽는다.

완료 조건:

- T14·T15 추천 순서와 점수가 참조 구현과 일치한다.
- 각 추천 결과에 `fixedNutrients`, `margin`, `overlap`, `scoreBreakdown`을 반환한다.

### P1. API와 결과 모델

**BE-V3-014 분석 결과 스키마 명시**

- Pydantic 응답 모델을 추가한다.
- `standardProfile`, `standardVersion`, `parameterVersion`, `lifeStage`, `energy`, 성장 계산 상세, 성분별 선·섭취량·근거·상태, Ca:P, 경고를 타입으로 고정한다.
- `dict` 자유 형식 응답을 제거한다.

**BE-V3-015 미지원과 오류 계약 분리**

- 8주 미만은 정상 응답의 `UNSUPPORTED`로 돌려줄지 422로 막을지 API 계약을 정한다.
- 체급 누락, 지원하지 않는 단위, 데이터 부족, 제품 미존재에 안정적인 오류 코드를 부여한다.
- 임신·수유 미지원 상태도 프로필 모델에서 명시한다.

**BE-V3-016 기준·매개변수 조회 API 추가**

- `GET /api/v2/standards/{profile}`: 활성 성분, 단위, 생애주기별 기준, 출처 상태.
- `GET /api/v2/parameters/{profile}`: 공개 가능한 정책 매개변수.
- 프런트가 하드코딩 없이 지원 범위와 안내 문구를 그릴 수 있게 한다.

### P1. 검증과 운영

**BE-V3-017 T1~T16 골든 테스트 이식**

- ZIP의 참조 구현을 테스트 입력·기대값의 근거로 사용한다.
- 에너지, 성장곡선, 기준선, 추정 사료, 판정 순서, Ca:P, 추천 순서를 검사한다.
- 부동소수점 허용 오차를 명시한다.
- 현재 FEDIAF 17개 테스트는 유지해 기존 기준 프로필의 회귀를 막는다.

**BE-V3-018 데이터 무결성 테스트 추가**

- 44개 ID 연속성·고유성, 구현 18개 목록, 단위 유효성, null 보존, 최소≤주의≤상한 관계를 검사한다.
- 주의선만 있는 성분은 상한이 없어도 활성화할 수 있어야 한다.
- 출처 검증 상태와 실제 활성화 상태가 일치하는지 검사한다.

**BE-V3-019 계산 추적 로그와 재현성 추가**

- 입력 해시 외에 기준 데이터 체크섬과 매개변수 체크섬을 결과에 포함한다.
- 같은 버전·입력은 UUID를 제외한 계산 결과가 동일해야 한다.
- 로그에는 개인정보 대신 trace ID, 버전, 실패 코드만 남긴다.

**BE-V3-020 성능·부하 검증**

- 44개 성분, 제품 20개, 추천 후보 수백 개 조건에서 응답 시간을 측정한다.
- 해시 조회, 고정 배열 누적, 최대 힙 선택이 실제 실행 경로에 유지되는지 회귀 테스트 또는 벤치마크로 확인한다.

## 권장 구현 순서

1. BE-V3-001~004: 기존 엔진과 새 기준을 분리하고 데이터 스키마를 확정한다.
2. BE-V3-005~009: 생애주기·열량·기준선·합산을 구현한다.
3. BE-V3-010~011: 단위와 제품 적재 경계를 완성한다.
4. BE-V3-017~018: T1~T16과 데이터 무결성 테스트를 먼저 통과시킨다.
5. BE-V3-012~013: 추천 점수와 체중별 용량을 맞춘다.
6. BE-V3-014~016: API v2와 프런트 연결 계약을 확정한다.
7. BE-V3-019~020: 재현성·성능을 검증한다.

## 출시 차단 조건

- NIAS 원문 표의 수치·단위가 독립적으로 대조되지 않았다.
- EU 법정 주의값의 FEDIAF 원문 대조가 끝나지 않았다.
- 18개 구현 성분 목록이 팀에서 확정되지 않았다.
- 기존 FEDIAF 모드와 NIAS v3 결과를 사용자가 구분할 수 없다.
- 부분 성분표의 누락값을 실제 0으로 계산한다.
- 추천이 현재 급여 제품을 다시 추천하거나, 평균 안전 여유로 위험 성분을 가린다.

## 발표용 설명

백엔드는 기준 데이터를 계산 코드와 분리하고 버전별로 불러온다. 제품은 해시 테이블로 조회하고, 성분은 고정 순서 배열에 누적한다. 각 성분의 하한·주의·상한은 개체의 기준 열량에 맞춰 하루 값으로 바꾼다. 추천은 후보를 넣은 결과를 다시 판정한 뒤 최대 힙에서 점수가 가장 높은 제품을 하나씩 선택한다. NIAS v3를 추가해도 기존 FEDIAF 결과는 별도 버전으로 남기므로 기준이 섞이지 않는다.
