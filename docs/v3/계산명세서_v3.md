## 1. 나이 정규화

```
weeks  = age_value              (age_unit == "week")
       = age_value × 4.345      (age_unit == "month")
months = weeks ÷ 4.345
```

두 값을 모두 들고 다닌다. 주 경계(8주, 14주)는 `weeks`로, 개월 경계(4, 9, 12)는 `months`로 비교한다.

---

## 2. 생애주기 판정 `life_stage(species, weeks, months)`

```
dog:
  weeks  <  8            → "unsupported"
  weeks  < 14            → "dog_early"
  months < 12            → "dog_late"
  else                   → "dog_adult"

cat:
  weeks  <  8            → "unsupported"
  months <= 4            → "cat_s1"
  months <= 9            → "cat_s2"
  months < 12            → "cat_s3"
  else                   → "cat_adult"
```

생애주기 → 기준값표 열 매핑:

| 생애주기 | min 열 | max 열 | 성장기 여부 |
|---|---|---|---|
| dog_early | dog_early | dog_growth | 예 |
| dog_late | dog_late | dog_growth | 예 |
| dog_adult | dog_adult | dog_adult | 아니오 |
| cat_s1 / s2 / s3 | cat_growth | cat_growth | 예 |
| cat_adult | cat_adult | cat_adult | 아니오 |

`unsupported`이면 이후 계산을 하지 않고 모든 성분을 "미지원"으로 반환한다.

---

## 3. 강아지 성장 정보 `puppy_growth(weight, weeks, size_class)`

생애주기가 dog_early 또는 dog_late일 때만 호출한다. `size_class`가 null이면 오류 "체급 선택 필요"를 반환하고 계산을 멈춘다.

```
c        = growth_curve[size_class]
pct      = c.a × ln(weeks) − c.b
pct      = min(pct, 100)                         # 100 초과 절단
adult_raw = weight ÷ (pct ÷ 100)                 # 예상 성체 체중(절단 전)
adult    = clamp(adult_raw, c.lo, c.hi)          # hi가 null이면 하한만 적용. lo는 "초과"이므로 lo 이하면 lo로 둔다
warning  = (adult_raw < c.lo) or (c.hi != null and adult_raw > c.hi)   → "체급 또는 체중을 확인하세요"
k        = pup_a − pup_b × (pct ÷ 100)           # = 254.1 − 1.35 × pct
ca_large = (adult >= ca_large_kg)                # 칼슘 4.5 적용 여부
return k, adult, ca_large, warning
```

`pct`는 8주 이상에서 항상 양수다(최소 체급 8주: 36.92 × ln 8 − 43.57 = 33.2).

## 4. 기준 열량 `energy(species, stage, weight, k)`

```
k =  dog_adult            → k_adult.dog (110)
     dog_early / dog_late → puppy_growth().k
     cat_adult            → k_adult.cat (100)
     cat_s1 / s2 / s3     → k_adult.cat × cat_mult[stage]

E = k × weight ^ exp[species]
```

---

## 5. 성분별 기준선 `thresholds(nutrient, species, stage, E, ca_large)`

모든 값은 1일 섭취량 단위(기준값표의 단위 그대로).

```
min_ref = nutrient.min[min열]                     # null 가능
max_ref = nutrient.max[max열]                     # null 가능
if nutrient is 칼슘 and stage in (dog_early, dog_late) and ca_large:
    max_ref = ca_max_large (4.5)

lower  = null if min_ref is null else E ÷ 1000 × min_ref
upper  = null if max_ref is null else E ÷ 1000 × max_ref

exc = nutrient.caution[species]                   # 예외 주의값
if exc is not null:            caution = E ÷ 1000 × exc
elif upper is not null:        caution = upper × caution_ratio[species]
else:                          caution = null
```

주의 시작값의 우선순위는 예외 주의값 → 상한 × 임계값 → 없음이다. 개의 비타민 A는 예외 주의값(62,500)이 있고 상한(100,000)도 있으므로 caution = E ÷ 1000 × 62,500, upper = E ÷ 1000 × 100,000이 된다.

---

## 6. 섭취량 합산 `intake(profile, feeding, thresholds)`

성분 i마다:

```
# 사료 몫
if feed != null and feed.has_detail and i in feed.contents:
    feed_part = feed.contents[i] × feed.grams_per_day
    feed_estimated = false
elif complete_feed and lower[i] != null:
    feed_part = lower[i] × feed_factor
    feed_estimated = true
else:
    feed_part = 0
    feed_estimated = false

# 영양제
supp_part = Σ  supplements[s].contents[i] × doses_per_day     (i가 contents에 없으면 0)

total[i] = feed_part + supp_part
```

`feed_estimated`는 그래프에서 추정 막대를 구분하고 안내 문구를 띄우는 데 쓴다. 단위 환산은 여기서 하지 않는다. 제품 데이터를 입력할 때 기준값표의 단위로 이미 환산되어 있어야 한다.

---

## 7. 판정 `judge(total, lower, caution, upper, stage)`

```
if stage == "unsupported":                          → "미지원"
if lower is null and upper is null and caution is null:   → "기준 없음"
if lower is not null and total < lower:             → "부족"
if upper is not null and total > upper:             → "과다"
if caution is not null and total >= caution:        → "주의"
if upper is not null:                               → "적정"
else:                                               → "적정(상한 기준 없음)"
```

순서를 바꾸면 안 된다. 특히 "과다"가 "주의"보다 먼저다.

---

## 8. 칼슘:인 비율 `ca_p_ratio(total_ca, total_p, species)`

개에만 적용한다. 고양이는 "해당 없음"을 반환한다.

```
if total_p == 0 or total_ca is null or total_p is null:  → "계산 불가"
r = total_ca ÷ total_p
r < ca_p_min (1)   → "비율 낮음"
r > ca_p_max (2)   → "비율 높음"
else               → "적정"
```

칼슘과 인의 단위는 둘 다 g이어야 한다(기준값표 기준).

---

## 9. 전체 흐름 `analyze(profile, feeding)`

```
1. weeks, months  = normalize_age(profile)
2. stage          = life_stage(species, weeks, months)
   if unsupported → return 전 성분 "미지원"
3. if stage is 강아지: k, adult, ca_large, warning = puppy_growth(...)
   else: k = 4장의 규칙, ca_large = false
4. E = k × weight ^ exp
5. for each nutrient (implemented == true):
      lower, caution, upper = thresholds(...)
6. total, feed_estimated = intake(...)
7. for each nutrient: status = judge(...)
8. if dog: ratio_status = ca_p_ratio(total[칼슘], total[인])
9. return { stage, E, warning, per_nutrient: [ {id, lower, caution, upper, total, feed_part, supp_part, feed_estimated, status} ], ratio_status }
```

## 10. 추천 `recommend(profile, feeding, analysis, candidates)` — A안: 부족 보완 + 안전 확인

관심사(태그) 항목은 1차 구현에서 뺀다. 제품 데이터의 `tags` 필드는 비워 두고, 나중에 B안(관심사 기반 추천)을 추가할 때 쓴다.

### 10.1 점수식

```
점수 = w2 × 보완 수  +  w3 × 안전 여유  −  w4 × 중복 수

보완 수   = 현재 "부족"인 성분 중 추가 후 "부족"이 아니게 되는 성분 수
안전 여유 = 상한 있는 성분들 중 최솟값 of (caution − trial) ÷ (caution − lower)
            · 0(주의선 직전) ~ 1(하한에 붙어 있음)
            · trial < lower인 성분은 1로 본다
            · 후보 제품이 상한 있는 성분을 하나도 담고 있지 않으면 1
중복 수   = 후보의 contents 키 ∩ (현재 급여 중인 영양제들의 contents 키 합집합)
```

기본 가중치(매개변수표): w2 = 10, w3 = 5, w4 = 1, top_n = 3.

### 10.2 절차

```
current  = analysis.total                       # 성분별 배열
deficits = { i | status[i] == "부족" }
chosen   = []
repeat top_n times:
    heap = 최대 힙
    for c in candidates (영양제; 이미 급여 중 또는 chosen이면 제외):
        dose  = c.dose_by_weight에서 weight_kg 이하 첫 구간의 dose
        trial = current + c.contents × dose
        st    = { i: judge(trial[i], lower[i], caution[i], upper[i], stage) }
        if any st[i] in ("주의", "과다"): continue          # 1단계 거르기
        fixed = |{ i ∈ deficits : st[i] != "부족" }|
        margin = 10.1의 안전 여유
        overlap = 10.1의 중복 수
        heap.push( w2 × fixed + w3 × margin − w4 × overlap, c )
    if heap 비어 있음: break
    best = heap.pop()
    chosen.append(best)
    current = current + best.contents × best.dose
    deficits = { i | judge(current[i], ...) == "부족" }
return chosen
```

### 10.3 화면 표시

- `deficits`가 비어 있지 않으면: "부족 성분을 보완하는 추천 조합"으로 표시하고, 각 제품에 보완되는 성분명을 붙인다.
- `deficits`가 비어 있으면(완전사료 급여 중인 대부분의 경우): "현재 조합에서 부족한 성분은 없습니다. 아래 제품은 추가해도 주의 구간에 들지 않습니다"로 표시한다. 순위는 안전 여유 순이다.
- 통과 후보가 없으면: "현재 조합에 추가할 수 있는 제품이 없습니다."

### 10.4 한계 (보고서에 적을 것)

완전사료 급여를 가정하면 부족 판정이 나오지 않으므로, 이 추천은 "필요한 영양제 찾기"가 아니라 "추가해도 안전한 영양제 확인"으로 동작한다. 필요 성분 기반 추천은 제품 카테고리 태그와 관심사 입력(B안)을 추가하면 같은 구조에 가점 항목 하나를 더하는 것으로 구현할 수 있다.

## 12. 구현 시 주의

- 기준값의 null은 0으로 바꾸지 않는다. 0이 되면 `total > upper`가 항상 참이 되어 모든 성분이 "과다"가 된다.
- 부동소수점 비교는 그대로 해도 된다. 화면 표시만 소수 둘째 자리(IU는 정수)로 반올림한다.
- 나이 단위를 개월로 받은 강아지의 14주 경계 판정은 4.345 환산값으로 한다. 3개월 = 13.0주이므로 초기 성장이다.
- `ln`은 자연로그다. 성장곡선은 주령 8~52에서만 정의되어 있고, 52주를 넘겨도 12개월 미만이면 그대로 계산하되 pct는 100에서 절단된다.
- 추천의 1단계는 7장의 `judge`를 그대로 재사용한다. 별도 판정 로직을 만들지 않는다.
- 가중치 w2·w3·w4와 top_n은 매개변수표에서 읽는다. 코드에 상수로 박지 않는다.
